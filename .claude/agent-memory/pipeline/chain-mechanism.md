The fallback-CHAIN mechanism (escalation via `ScoreBelow` + fall-through via `OnFailure`, convergence via `FromFirst`).

**Where chains are wired today (post-P3):** the reusable chain TOPOLOGY lives in `shared/libs/pipelines/build/chain.py` (`ChainFragmentBuilder` + `ChainFragment` + `ChainStepSpec`) — pure, imports only `base`+`build/blob`, MUST NOT import `ingest/`. Two CALLERS: (1) `enrich_body.py` (per-figure sites, keeps the `WhenEquals` entry edge + OCR model-free `figure_entry` terminal); (2) `stages/segments.py::SegmentBuilder.__parse` (the PARSE stage itself, P3). Embed/metagen/contextualize-llm still have NO fallback (P4..P6 pending).

**PARSE (P3) + EMBED (P4) are chain-capable:** `PipelineState.parse_chain`/`embed_chain: ChainSpec` REPLACED `parser_kind`/`parser_config` and `embed_kind`/`embed_config` (grep all four — they must not exist anywhere). A single provider is a **1-step ChainSpec** whose segment is the lone `parse`/`embed` node (byte-identical default). `SetProvider(<stage>, kind)` is sugar for a 1-step chain; `SetChain(stage=…, slot=None, steps=…)` builds the real chain; `SetStageConfig(<chain-stage>)` edits the head step's config. `_Segment.output` (in `stages/segments.py`) is the SINGLE source of truth for a stage's downstream anchor — `FromNode` for a stock stage, the chain's `FromFirst` for a chain; the assembler's `__bindings` reads `segment.output`, never re-derives literals, so exits + convergence can't drift. Layer split: `segments.py` (SegmentBuilder + Segment), `assembler.py` (spine threading only), `chain_rules.py` (build-safe config defaulting + family chain rules).

**PARSE vs EMBED chain differences (the P4 gotchas):** (1) parser is **scored** → `ScoreBelow`+`OnFailure` escalation; embed is **NON-scored** (`EmbedProduces` ≠ ScoredOutput) → `SegmentBuilder.__embed` passes `scored=False`, so **OnFailure-only** (no ScoreBelow) — a `score_below` on an embed step is dropped with the "failure-only for this family" notice. (2) Both embedders (`bge_server`, `openai_compatible`) are `UNIQUE_IN_GRAPH=True` → a chain may only mix the **two DIFFERENT kinds** (max len 2); a duplicate → "can appear only once" notice AND the validator's `duplicate_unique_node` at build. (3) **Static vs dynamic consumed face:** parse's step face (`source`=address.ingest) is static → the parse segment self-carries `bindings`; embed's face (`chunks` spine + `contract`) depends on the enabled chunks-spine stages so it's NOT known in SegmentBuilder → `__embed` carries NO bindings and the assembler threads the face onto **every embed step id** (`for step_id in by_key["embed"].exits`). The bundle's `embeddings` reads `by_key["embed"].output` (the convergence). (4) embed is a removable TOGGLE → `compiler.__restore_defaults` restores the stock 1-step embed chain when the head config is empty (mirrors the old `embed_config` restore). `bge_server` config: `model` defaults `BAAI/bge-m3`, `base_url` is REQUIRED — the builder DOES `Config.model_validate` (a bare `{}` config fails build), which is why the compiler runs `ChainRules.complete_steps` (fills required → `""` build-safe) and the stock default sets `base_url` explicitly.

**`SetChain.slot` is now optional:** present → an enrich per-figure site; **absent (None) → the stage itself is the chain** (routed via `compiler._CHAIN_STAGES = {PARSE: ("parse_chain","parser")}`). Compiler notices (DATA, never raise): empty chain on a required non-removable stage → keep prior + notice; `score_below` on a non-scored family → strip it + notice (parser IS scored so no-op there — guards P4 embed); duplicate `UNIQUE_IN_GRAPH` kind in a chain → notice before the build rejects it. The reader walks the parse chain family-first over `blob.transitions` (generalized `__walk_chain(transitions, by_id, head, families)`), round-tripping a stable ChainSpec.

**Builder contract subtlety (byte-identical caveat):** `ChainFragmentBuilder.build(*, prefix, family, steps, step_inputs, output_field, scored)`. Node ids = `f"{prefix}_{i}"`. Per adjacent pair it emits `ScoreBelow` (iff `scored and step.score_below is not None`, else dropped + `dropped_score_below=True`) THEN always `OnFailure`. `output` = `FromNode` for N==1, `FromFirst([...reversed])` for N>=2. NOTE: the OLD enrich `__close_ocr` used `FromFirst([FromNode])` even for a 1-step OCR chain; the builder now gives a bare `FromNode` there — a semantically-equal divergence that is INVISIBLE because the default blob's only OCR chain (`scanned_text_ocr`) has 2 steps and no existing test dumps a 1-step-OCR terminal. Golden proof: `default_blob()` per_figure body is byte-identical before/after.

**Load-bearing gotchas for generalizing chains:**
- `scored` is AUTO-DERIVED, not declared: `base/node.py:194` sets `scored=issubclass(cls.Produces, ScoredOutput)`. A chain builder must only emit `ScoreBelow` for families whose `Produces` subclasses `ScoredOutput` (parser, ocr, vlm, figure_classify). Validator enforces it (`validator.py:297` SCORE_BELOW_NOT_SCORED). llm/embed/metagen/contextualize are NOT scored → `OnFailure`-only chains.
- **Both embedders are `UNIQUE_IN_GRAPH=True`** (`embed/bge_server` AND `embed/openai_compatible`). So an embed fallback chain can only mix DIFFERENT kinds (bge_server→openai_compatible); two openai_compatible endpoints are rejected at build (`duplicate_unique_node`). This caps embed chains hard.
- The ingest "llm sites" are the `metagen` (document/chunk) and `contextualize`/`llm` families — NOT the generic `llm` family (`nodes/llm/`, produces `{completion}`, unused in ingest). metagen document/chunk and contextualize/llm are NOT unique → chainable by repeating the node with different endpoints, `OnFailure` only.
- Validator single-path rule (`validator.py:313`): ≤1 outgoing transition per condition KIND per node (except WhenEquals). So one step may carry `ScoreBelow→next` + `OnFailure→next` + `OnSuccess→exit` simultaneously (distinct kinds) — this is how a linear chain's success-exit coexists with escalation. Proven by enrich already validating.
- Bare `Transition(a,b)` defaults to `OnSuccess` (`transition.py:102`).

**Stage-rail surface:** `StageKind` has FIXED/TOGGLE/PROVIDER/STACK — NO `CHAIN`. `SetChain`/`compiler.__set_chain` target ONLY enrich (`stage != ENRICH` → notice). `StateReader.__derive_chains` walks chains out of the ForEach body only. Generalizing means teaching the assembler/reader that a linear provider stage's "output" can be a `FromFirst` convergence, not a single `(node,field)`.

**Reusable machinery that already exists:** `GroupNodeBlob` (a fragment) · `edit/fragment.py FragmentRemap` (id-disambiguation + recursive remap) · `edit/operations.py InsertFragment`. But the linear-pipeline splice needs a new seam (multi-exit segment + convergence binding) — FragmentRemap alone doesn't rebind downstream consumers.
